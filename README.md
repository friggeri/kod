# Kod

Kod is a native, strictly read-only macOS code viewer. The product and technical requirements are in [SPEC.md](SPEC.md). Privacy details are in [docs/privacy.md](docs/privacy.md); support/troubleshooting guidance is in [docs/support.md](docs/support.md); the manual VoiceOver release checklist (never run by any automated agent) is in [docs/manual-voiceover-checklist.md](docs/manual-voiceover-checklist.md); release packaging/signing/notarization is in [Scripts/release/README.md](Scripts/release/README.md); Intel/x86_64 compatibility evidence and its limits are in [docs/intel-compatibility-report.md](docs/intel-compatibility-report.md).

## Requirements

- macOS 14 or later
- Xcode 26 or later
- Swift 6

## Language support

Kod bundles offline, quality-gated Tree-sitter syntax highlighting for Swift,
TypeScript/JavaScript, HTML, CSS, Python, Rust, shell, Markdown, JSON, YAML,
TOML, C, Go, Java, Ruby, Lua, GraphQL, and XML. Markdown uses coordinated
block and inline grammars and highlights fenced code when the referenced
grammar is also built into Kod. Shell detection covers common filenames plus
Bash/sh shebangs. Unsupported mappings fall back safely to Plain Text.

**Language-server executables are not bundled or installed by Kod.** Shipped
language profiles map files to bundled syntax and may discover a known server.
**Kod → Settings…** uses one native sidebar for Font and the shipped language
catalog. Selecting a language shows only its server status, effective Command,
concise detected version/name metadata, and curated installation guidance when
the server is not installed. File
associations remain fixed shipped metadata. Command text is parsed locally into
an absolute executable path and argument array and is never passed to a shell.
The multiline field wraps long commands and accepts newlines as token
separators.
Kod restores the last known Ready/Not Installed states immediately, then
refreshes the full shipped catalog asynchronously when the app launches.
Unknown file types offer a contextual GitHub language request instead of
creating a syntax-less custom profile.
Workspace trust is required before any selected or discovered server starts;
syntax highlighting and search remain available without a server.

## Build and test

The repository has two local Swift packages with no remote package
dependencies:

- `Packages/KodCore` owns portable models, parsers, transports, persistence,
  and `KodBuildInfo`. Its `KodCore` product is intentionally build metadata
  only; consumers link the focused products they use.
- `Packages/KodUI` owns `KodUIComponents`, `SearchUI`, `PreviewUI`, `GitUI`,
  and `EditorUI`. The Xcode app target is the composition/session shell.
- `App/KodApp`, `App/KodAppTests`, and `App/KodAppUITests` are
  filesystem-synchronized Xcode roots. The app shell and unit tests are
  organized by feature, so adding or moving files below those roots does not
  require editing `project.pbxproj`.

Run the cumulative verification gate for the current implementation phase:

```sh
Scripts/verify-phase 12
```

Or open `Kod.xcodeproj` and run the `Kod` scheme.

Set `KOD_RUN_SCALE_TESTS=1` to additionally run the 100,000-file discovery scale gate (skipped by default; it generates a large local fixture and is slow).

Language adapter integration tests require the pinned real servers listed in `Scripts/vendor-test-language-servers/manifest.json`, including the first-wave shell, Markdown, JSON, YAML, and TOML servers. Run `Scripts/vendor-test-language-servers/setup.sh` once (or after a clean checkout) to install them.

Phase 2 adds one-root workspaces, root-first lazy Explorer discovery, workspace trust, recent roots, and path-aware Quick Open with a deferred breadth-first filename index on top of the immutable source viewer.

Phase 3 adds a complete plain-text viewing workflow: preview and pinned tabs with reordering, nested horizontal/vertical split editor groups with an independently active group, per-group Back/Forward navigation that restores file, selection, and viewport, Find in File (plain, case-sensitive, whole-word, and regex modes) with result navigation, Go to Line, a word-wrap toggle (default off, without weakening the 10 MB fast path), a Command Palette, native menu/shortcut wiring, and external metadata persistence for window/split/tab/navigation/selection/scroll state that never writes into the opened workspace.

Phase 4 adds real syntax and visual customization on top of the plain-text viewer:

- **`SyntaxCore`**: pinned, compiled-in Tree-sitter grammars (via vendored `CTreeSitter*` packages; see [THIRD_PARTY_NOTICES.md](THIRD_PARTY_NOTICES.md)) for Swift, TypeScript, JavaScript, HTML, CSS, Python, Rust, shell, Markdown, JSON, YAML, and TOML — no runtime grammar-extension mechanism. Snapshot-versioned, viewport-prioritized highlight captures feed a versioned decoration compositor with layers for lexical syntax, and slots prepared for future semantic tokens, search, and diagnostics; results for a superseded snapshot are discarded rather than painted.
- **`CodeViewport`** now paints real lexical syntax colors (first paint stays plain-text and independent of parsing), structural code folding, indentation guides, matching-bracket highlighting/navigation, and sticky scope headers, all through the existing source/visual mapping and word-wrap machinery.
- **`SettingsCore`**: dependency-light, typed settings persistence with explicit UserDefaults/in-memory adapters, versioned Codable envelopes and migrations, semantic validation, owned observation cancellation, and bounded redaction-safe corrupt-state quarantine. Domain keys and models remain in their owning modules.
- **`ThemeCore`**: a versioned native theme schema and PVC-derived Kod Light and Kod Dark definitions; the app automatically resolves between them from the current macOS appearance.
- **`FontCore`**: searchable installed-monospaced-font discovery and settings for family, size, weight, ligatures, line height, and letter spacing, applied live and persisted outside any workspace; AppKit/Core Text supplies glyph fallback automatically.
- A native Settings window (`Kod > Settings...`, ⌘,) for font and language configuration, plus `Toggle Fold` and `Go to Matching Bracket` menu commands.
- Source-code surfaces include a default-on, right-side proportional minimap. It overlays the source content without shrinking the viewport, keeps the native vertical scroller on its right, and distinguishes its transparent token raster with a subtle appearance-aware semantic tint over the window material. It reuses `CodeViewport`'s wrapped/folded/view-zone visual rows and composed token colors, keeps only viewport-sized raster buffers, overlays selection, all in-file find matches, normalized LSP diagnostics, and primary/secondary Git changes, and supports click-to-center plus continuous slider dragging. `View > Minimap` persists per workspace; standalone source windows preserve the toggle when their language profile rebuilds the document controller. Rendered previews, binary/image views, and the separate patch-style full diff intentionally do not host it.

See `Scripts/vendor-tree-sitter/` for the exact pinned commits used to vendor the Tree-sitter runtime and grammars, and how to refresh them.

Phase 5 adds workspace search and live filesystem awareness:

- **`SearchCore`**: a bundled, version-pinned, licensed ripgrep-compatible engine (`rg` 14.1.1; see [THIRD_PARTY_NOTICES.md](THIRD_PARTY_NOTICES.md) and `Scripts/vendor-ripgrep/`) for both Apple silicon and Intel, launched only via an absolute executable `URL` and fixed argument arrays — never a shell string or `PATH` lookup. Streaming, bounded, incremental JSON output parsing yields UTF-8-safe match ranges; every query is cancellable and a new query supersedes (and terminates) any query already running; explicit result limits mark truncation instead of pretending a capped search finished; case, whole-word, regex, include/exclude globs, hidden files, and ignored files are all supported. The Search sidebar includes ignored files by default, while `.git` remains unconditionally excluded.
- A **Search sidebar** in the workspace window (toggle with the centered Explorer/Source Control/Search/Problems segmented control, or Command-Shift-F / the Command Palette) streams results grouped by file as they arrive; selecting a match opens it in the active editor group with the match selected.
- **FSEvents-based live updates**: workspace changes are coalesced across short write bursts, then applied incrementally — the Explorer tree and filename index update per changed path (using the same nested-`.gitignore`-aware classification as full discovery, not a full rescan) unless an ignore-defining file itself changed, in which case Kod safely falls back to a full rescan. Externally modified open files reload automatically into a new, version-bumped, immutable `SourceSnapshot`, preserving the nearest selection, viewport line, and code folds via a content-addressed reconciler. A deleted or moved open file becomes an explicit tombstone tab (visible until closed or the path becomes valid again) instead of silently disappearing or continuing to show stale content.
- Stale syntax, search, and reload results are rejected by snapshot/query version throughout, so a slow in-flight computation for a superseded snapshot or query can never overwrite what the user is currently looking at.

See `Scripts/vendor-ripgrep/` for the exact pinned commit, source checksum, and reproducible build script used to vendor the search engine, and how to refresh it.

Phase 6 adds a Swift LSP vertical slice on top of the syntax/search foundation:

- **`LanguageClient`**: a from-scratch JSON-RPC 2.0 / LSP 3.17 client — bounded `Content-Length` framing tolerant of arbitrarily fragmented reads, typed request/notification/response models for every capability implemented below, per-request timeouts, `$/cancelRequest` support (including automatic cancellation when Kod's own calling `Task` is cancelled), work-done progress (driving an explicit `indexing` state), and bounded rotating stderr capture. One dedicated actor owns each connection/process; every executable is launched via an absolute, pre-resolved `URL` with a fixed argument array — never a shell string or `PATH` lookup. A crashed server auto-restarts up to three times in five minutes (re-synchronizing every previously-open document via `didOpen` after each restart) before Kod disables it and requires a manual Restart.
- Kod's advertised capabilities during `initialize` are strictly read-only: no `workspace.applyEdit`, rename, code actions, formatting, `workspace/executeCommand`, or file operations, and no dynamic registration for anything Kod implements. Every outgoing request is drawn from a fixed allow-list (there is no generic "send any request" escape hatch), and any server-initiated `client/registerCapability`/`workspace/applyEdit` is rejected with an explicit JSON-RPC error rather than silently accepted or ignored.
- **`SourceKitLSPDiscovery`** resolves Swift's language server exclusively through `xcrun --find sourcekit-lsp` at its fixed absolute location — never a shell string or cached guess — with one process started lazily per trusted Swift workspace, only after `WorkspaceTrustStore` confirms trust.
- **`SwiftWorkspaceLanguageService`** synchronizes each open Swift document as an immutable, versioned `SourceSnapshot` (`didOpen`/`didChange`/`didClose`), negotiates UTF-8 positions where a server supports them and otherwise maintains the existing tested UTF-16 mapping, and validates every returned URI/range/snapshot version before use — a stale or out-of-bounds response is discarded rather than shown. It implements hover, definition, references, document/workspace symbols, push diagnostics (including unopened files inside the trusted workspace), capability-gated document and workspace pull diagnostics, and full semantic tokens, which feed the existing decoration compositor's `.semantic` layer above lexical highlighting.
- The workspace sidebar gains a **Problems** surface (alongside Explorer/Search/Source Control) plus a server-state indicator (Missing/Starting/Indexing/Ready/Busy/Stopped/Crashed/Disabled) with a manual Restart action. Problems is the owner-aware union of diagnostics published by every active language service; identical cross-owner entries are collapsed only for display. Servers advertising LSP 3.17 workspace diagnostics are pulled after activation and on refresh, while other servers contribute only through their existing lazy activation/open-document lifecycle. Kod never opens every file or launches every configured server just to populate Problems. Syntax highlighting and text search remain fully usable when a language server is absent, still starting, or has crashed.
- A deterministic, scenario-driven **`FakeLanguageServer`** stdio fixture (built as a separate executable target, reusing `LanguageClient`'s own framing/encoding code) exercises fragmented frames, malformed/oversized payloads, cancellation, timeouts, work-done progress, bounded stderr, crashes and restart, adversarial dynamic-registration/`applyEdit` attempts, and invalid/stale ranges — all headless, no real language server involved.
- Real, headless `sourcekit-lsp` integration tests run against a small checked-in fixture Swift package (`Packages/KodCore/Tests/LanguageClientTests/Fixtures/SourceKitLSPFixture`), with a normalized recorded transcript of one session checked in alongside them for reference. **Known, documented limitation for the SourceKit-LSP shipped with this Xcode toolchain:** it does not declare `positionEncoding` (Kod correctly falls back to UTF-16) and does not advertise `diagnosticProvider` even though it implements pull diagnostics informally — Kod capability-gates pull diagnostics off for this server and relies on push (`textDocument/publishDiagnostics`) instead, exactly as SPEC 6.4's "publish and pull diagnostics" wording anticipates for servers where only one is applicable.

Phase 7 completes the read-only LSP product across every launch language:

- **Complete capability surface.** `LanguageClient` now models and capability-gates declaration, type definition, implementation, document highlight, workspace symbols, pull diagnostics, inlay hints, explicit signature help, call hierarchy, type hierarchy, folding ranges, selection ranges, and safe document links, alongside Phase 6's hover/definition/references/document symbols/semantic tokens/push diagnostics. Every result is validated the same way Phase 6's were: cross-file navigation targets (definition/declaration/type-definition/implementation/references/hierarchy items) are validated structurally (absolute `file://` URI, non-negative, non-inverted range) and bound to the provider that produced them — a `LanguageProviderID`, that provider's connection generation, and the position encoding it negotiated — so a target is converted and re-requested through its originating server rather than one inferred from its target URL; same-document results (hover, document highlight, folding/selection ranges, inlay hints, document link ranges) are validated against the requesting snapshot's actual UTF-8 bounds; an out-of-bounds or malformed result is discarded, never shown. Document links additionally reject any non-`file`/`https`/`http` target (e.g. a `command:` URI some servers use to trigger client-side actions) outright — `SafeDocumentLink.validating(_:)` — since Kod must never treat a server-supplied link as something to execute.
- **Dynamic registration for read-only capabilities.** `LanguageServerConnection` now inspects a `client/registerCapability` batch and accepts it only if every registered method is one Kod already knows how to use read-only; a batch containing even one mutating or unrecognized method is rejected in full (no partial acceptance), and `client/unregisterCapability` is always accepted (removing a registration can never grant a new capability). This lets a server that only advertises certain read-only features dynamically (rather than in `initialize`) still work, while the "reject every mutating registration" guarantee from Phase 6 is unchanged.
- **`LanguageWorkspaceService`**, a new language-agnostic engine implementing the complete capability surface above (lifecycle, document sync, capability gating, validation) shared by every adapter. `SwiftWorkspaceLanguageService` is now a thin wrapper around it — its own public API and error type are unchanged from Phase 6 — so Swift and every other language share one implementation rather than five parallel ones.
- **`LanguageAdapters`**, a package with deterministic local executable discovery: explicit paths stored outside the repository, language-specific system discovery (`xcrun --find sourcekit-lsp`, `rustup which rust-analyzer`), a captured login-shell `PATH`, and common package-manager locations. Every tier only ever launches a fixed, absolute executable with a fixed argument array or reads a fixed list of directories; nothing evaluates a shell string or repository-provided command. Every resolved executable reports its absolute path, best-effort version, provenance, and launch arguments before first use.
- Default profiles cover Swift, TypeScript/JavaScript, HTML, CSS, Python, Rust, shell, Markdown, JSON, YAML, TOML, C, Go, Java, Ruby, Lua, GraphQL, and XML. They provide bundled Tree-sitter syntax independently from optional local language-server discovery.
- **`MultiLanguageServicesCoordinator`** owns one generic `LanguageWorkspaceService` per active profile and workspace, including Swift. Services restart and documents resynchronize when a profile or selected executable changes. It also keeps a provider-ID-to-service routing table: hierarchy expansions go back to the exact service (and generation) that produced the item — opaque hierarchy `data` is never sent to a server inferred from the item's URL — and a handle whose provider was stopped, replaced, or restarted fails with a typed `LanguageProviderRoutingError` instead of being silently rerouted.
- **Peek Definition and Call Hierarchy** are real, reachable Command Palette commands for the active Swift document: `PeekViewController` shows a durable, always-replaced-wholesale list of validated navigation targets (never a raw, unvalidated server response); `HierarchyViewController` is a lazily-expanding, mode-switchable (Callers/Callees, or Supertypes/Subtypes for type hierarchy) outline over `ValidatedHierarchyItem`, reusable for both call and type hierarchy. Both are presented as sheets (`PeekPanelController`/`HierarchyPanelController`) and validated only through headless controller tests — no UI automation.
- **`FakeLanguageServer`** gained scenarios for every new capability, a `capability-absent` scenario (proving Kod hides/disables a feature rather than erroring when a server never advertises it), read-only-vs-mixed-batch dynamic-registration scenarios, and an unsafe-`command:`-URI document-link scenario.
- **Real, headless integration tests** run against pinned versions of every new server (`typescript-language-server` 4.3.4, `vscode-langservers-extracted` 4.10.0, Pyright 1.1.407, and `rust-analyzer` via a pinned `rustup` component) against small checked-in fixtures (`Packages/KodCore/Tests/LanguageAdaptersTests/Fixtures`). None of these servers are vendored, bundled, installed, or shipped by Kod; see `THIRD_PARTY_NOTICES.md` for their licenses.
- Repository-immutability and process-spy coverage extends to every adapter: each real-server integration test checksums its fixture file before and after exercising the adapter, and the generic `LanguageWorkspaceService` (shared by all five non-Swift adapters) has its own crash-loop/restart, capability-absence, and invalid-range-discard tests independent of `SwiftWorkspaceLanguageService`'s wrapper.

`Scripts/verify-phase` never launches `KodAppUITests`, `Kod.app`, `XCUIApplication`, or any GUI/AppleScript automation — this is a permanent restriction, not one later phases may relax.

Phase 8 provides fixed shipped language routing with command overrides:

- Each shipped profile maps extensions, exact filenames, and selected built-in content matchers to a bundled, quality-gated Tree-sitter grammar. File associations, grammar, and language IDs are shipped metadata rather than user settings.
- Each profile may discover a known server or store a selected absolute executable path and fixed argument array.
- Versioned defaults reset routing to the current shipped catalog while preserving Command overrides for profiles that still ship. Legacy custom and retired-profile records are discarded during schema migration.
- Kod never downloads, installs, updates, removes, or runs package-manager commands for a language server. A missing server's Settings detail surfaces copyable installation commands and official documentation from `DefaultLanguageServerInstallationGuides`; Kod never executes the displayed commands.
- Workspace trust remains mandatory before any selected or discovered server process starts. The editable Command field is deterministically parsed without shell expansion, interpolation, substitution, or execution.
- Bundled syntax expands with C, Go, Java, Ruby, Lua, GraphQL, and XML. Additional grammars ship only after license, provenance, parser/query quality, scanner safety, malformed-input, and size gates; unsupported mappings fall back to Plain Text.

Phase 9 adds hardened, read-only Git context (SPEC 9):

- **`GitCore`**, a new package invoking only an explicitly resolved, absolute Git executable (`GitExecutableLocator`, a fixed candidate list — Homebrew's Apple-silicon/Intel prefixes, then Apple's own Xcode Command Line Tools `/usr/bin/git` — never a `PATH`/shell lookup) with a fixed global argument prefix and minimal explicit environment (`GitInvocationHardening`): `--no-pager --no-optional-locks --no-replace-objects`, `GIT_OPTIONAL_LOCKS=0`, `GIT_TERMINAL_PROMPT=0`/a no-op `GIT_ASKPASS`/`GIT_SSH_COMMAND`, disabled hooks (`core.hooksPath=/dev/null`), fsmonitor (`core.fsmonitor=false`), external diff/textconv, color, and credential helpers, and `protocol.allow=never` (defense in depth; Kod never fetches or touches a remote). `GitReadOnlyCommand` is an exhaustive allow-list of read-only subcommands (`status`, `diff`, `blame`, `rev-parse`, `symbolic-ref`, `cat-file`, `ls-files`, `log`, `show`) — mirroring `LanguageClientOutboundMethod`'s allow-list discipline — so a mutating invocation is structurally impossible to construct from `GitCore`'s own code. `GitProcessRunner` (modeled directly on `SearchCore`'s `RipgrepProcessSession`) bounds stdout/stderr, enforces a timeout, and guarantees the child process is terminated on cancellation.
- **`GitRepositoryLocator`** detects a repository/worktree's root, its own (possibly linked-worktree-private) git-directory vs. the shared common directory, bare-repository state, and current branch or detached-`HEAD` commit id, via one combined `rev-parse` call plus `symbolic-ref`.
- **`GitStatusParser`** parses `git status --porcelain=v2 -z` (ordinary, rename/copy, unmerged, untracked, and ignored record shapes) into `GitStatusEntry`/`GitStatusSnapshot` — `-z` NUL-separation means every path (arbitrary bytes, Unicode, tabs) round-trips without Git's usual C-style quoting/escaping ever entering the picture.
- **`GitDiffParser`/`GitDiffService`** compute a file's diff against whichever of `HEAD`/index/working-tree applies (`workingTreeVsIndex`, `indexVsHead`, `workingTreeVsHead`), via a two-step, always-read-only invocation: a NUL-separated `--raw` call resolves exact add/delete/modify/rename/copy identity and old/new mode with no path-quoting ambiguity, then a patch call restricted (with `--`) to exactly the resolved path(s) produces hunks — passing both the old and new path together is what makes Git's own rename pairing work within a single pathspec-restricted call. Untracked files use `git diff --no-index` against `/dev/null` (the one invocation allowed to exit `1` as a normal "files differ" outcome). `GitSideBySideProjection` pairs each hunk's removed/added runs into side-by-side rows.
- **`GitBlameParser`/`GitBlameService`** parse `git blame --porcelain`: per-commit author/committer name/email/time/timezone/summary (cached the first time a commit id appears anywhere in the stream, exactly matching Git's own porcelain-omission behavior for repeated, even non-consecutive, occurrences), original/final line numbers, boundary commits, the synthetic all-zero "Not Committed Yet" uncommitted-line commit, and `previous`/`filename` rename-following metadata.
- **`GitRepositoryStateIdentity`/`GitResultCache`** key cached status/diff/blame results off `HEAD` + a plain `stat()` of the per-worktree index file + a generation counter `GitContext` bumps from the workspace's existing `WorkspaceFileWatcher` FSEvents pipeline — invalidating Kod's own in-memory cache only, never writing anything to `.git` or the working tree.
- **`GitContext`**, the single facade type App code holds per workspace: resolves the repository once, then serves cached/fresh status, diff, blame, and exact index/`HEAD` blob content. Virtual revision bytes pass through the same BOM, encoding, line-ending, and safety-mode decoder as filesystem snapshots.
- **GitUI presentation and App orchestration** (headless-only, per this script's permanent UI-automation restriction): the App-shell `GitWorkspaceCoordinator` owns a workspace's optional `GitContext` plus one immutable presentation index per snapshot, while KodUI's `SourceControlSidebarViewController` uses the VS Code default **Merge Changes / Staged Changes / Changes** grouping, mixes untracked files into Changes, hides ignored files, preserves collapsed sections, and renders path-sorted Material-icon rows with basename, muted parent path, rename context, themed group-specific status, and deletion strikethrough. Selecting a row opens VS Code-style **Quick Diff** in EditorUI: green added bars, blue modified bars, red deletion triangles, and a first-hunk inline `+`/`-` peek with stronger intraline highlights, previous/next, close, and **Open Full Diff** actions. Staged rows display the exact index snapshot against `HEAD`; ordinary visible source tabs show working-tree changes plus non-overlapping secondary staged indicators. Generic `CodeViewport` gutter and view-zone primitives keep Git out of source-text decoration composition and leave clean editors on the existing fast path. `GitDiffViewController` remains the secondary unified/side-by-side full viewer, while blame retains its line and commit-metadata views. Git themes include dedicated Quick Diff gutter plus line- and text-level inserted/removed background roles, import VS Code's `editorGutter.*Background` and `diffEditor.*Background` keys, and preserve legacy native-theme compatibility.
- **Deterministic fixtures** (`GitFixtureBuilder`, fixed `GIT_AUTHOR_DATE`/`GIT_COMMITTER_DATE`/identity/`GIT_CONFIG_GLOBAL=/dev/null`) build real repositories with commits, staged/unstaged edits, adds/deletes/renames/copies, real merge conflicts, ignored/untracked files, binary content, and multi-author/multi-timezone blame history; parsed Kod models are compared against independently-invoked real Git output (`GitStatusParserTests`/`GitDiffParserTests`/`GitBlameParserTests`).
- **`GitProcessSpy`**, a small executable standing in for the resolved Git binary in tests: it logs every invocation's exact argv/env to a file, then re-execs the real Git binary so functional behavior is unaffected while `GitProcessInvocationSpyTests` independently asserts the exact executable/arguments/environment used and the absence of any mutating, network, helper, or hook subcommand.
- **`GitImmutabilityTests`** take a SHA-256 (content + mtime + type) manifest of both the working tree and the entire `.git` directory before and after every workflow (status/diff/blame/repository-location, including with a deliberately backdated index to provoke Git's normal opportunistic index-refresh write-back) and require byte-for-byte equality — plus a regression guard that proves an *unhardened* `git status` really would have rewritten `.git/index`, so the assertion is demonstrably load-bearing rather than vacuous.
- **`GitPerformanceCancellationCacheTests`** cover status/diff/blame latency budgets, `GitProcessRunner` cancellation and timeout termination, bounded/truncated output, and `GitContext`/`GitResultCache` identity-based cache hits and invalidation.

Phase 10 adds safe built-in previews (SPEC 10):

- **`PreviewCore`** holds the preview subsystem. It uses Apple frameworks and Kod's own `SourceModel`/`SyntaxCore`/`ThemeCore`, plus the pinned, locally compiled `cmark-gfm` C targets used only for formal GFM parsing; SwiftPM has no remote package dependency. **`PreviewContentDetector`** dispatches by validated content (magic bytes for images; an HTML document signature; a `bplist00` signature or a recognized `UTType` for JSON/plist; content, never a path extension alone, decides) to one of `PreviewKind.markdown`/`.html`/`.image(ImageFormat)`/`.structuredData`/`.none`.
- **Markdown**: `MarkdownParser` remains the public facade but now converts a bounded `cmark-gfm` `0.29.0.gfm.13` tree into Kod's safe AST. It enables the complete formal GFM extension set (tables, task lists, strikethrough, extended bare URL/email autolinks, and tagfilter), deliberately does not enable footnotes, and does not add GitHub.com-only emoji/mentions/issue references/alerts/math/Mermaid. Source, block, inline-depth, node, and table-column limits are enforced during conversion with deterministic C-tree cleanup. `MarkdownDestination` still classifies every link/image destination so policy is enforced from data. Raw HTML still passes through the whole-source `DangerousElementStripper` and per-node `MarkdownHTMLSanitizer`, with every removal surfaced as a diagnostic. `MarkdownRenderer` continues to syntax-highlight fences through the same `SyntaxEngine`/theme pipeline as full source files. `MarkdownAttributedDocumentRenderer` then builds a native TextKit document: proportional system prose, configured monospaced inline/fenced code, heading rhythm/separators, inset quotes, nested ordered/unordered/task lists, full-width padded code blocks, real `NSTextTable`/`NSTextTableBlock` tables, links/tooltips, semantic image states, centered readable measure, and responsive insets. The pinned `github-markdown-css` commit is a design reference only; no CSS is shipped or executed.
- **HTML**: `HTMLPreviewDocument` recognizes real HTML document prefixes and injects a restrictive Content Security Policy. `HTMLPreviewViewController` uses an ephemeral `WKWebView` with page JavaScript disabled; scripts, network requests, frames, plug-ins, forms, and direct filesystem URLs are blocked. Relative images, stylesheets, fonts, and media resolve through a custom URL scheme whose loader revalidates workspace containment and symlinks before returning read-only bytes. Local links reopen in Kod, while external links retain the existing untrusted-workspace confirmation.
- **Images**: `ImageDecoder` decodes PNG/JPEG/GIF/HEIC/TIFF via ImageIO with every `ImageDecodeLimits` check (source size, per-frame dimension, per-frame pixel count, frame count, and a running total decoded-byte budget) applied against each frame's *declared* properties — read via `CGImageSourceCopyPropertiesAtIndex`, which parses only the container header — strictly before any pixel buffer is decoded, so a decompression bomb's true cost is caught without ever inflating it. SVG is deliberately never handed to ImageIO: `SVGSanitizer` (built on a from-scratch `LenientXMLTokenizer`) is a real allow-list sanitizer — only pure vector-drawing elements/attributes survive; `<script>`/`<foreignObject>`/`<style>`/animation elements are removed outright (via the same textual `DangerousElementStripper` pre-pass plus token-level filtering), external `href`/`xlink:href`/`url()` references are rejected unless a same-document `#fragment` or an inline `data:image/...` URI, and DOCTYPE/ENTITY declarations are never processed at all (the tokenizer skips markup declarations wholesale), which is what actually stops "billion laughs"-style entity-expansion and XXE attempts rather than merely disabling external-entity resolution. `SVGDocumentLoader` reports intrinsic size (from `width`/`height` or `viewBox`) alongside the sanitized XML.
- **JSON and property lists**: `JSONParser` is a hand-rolled, strict RFC 8259 parser (not `JSONSerialization`) chosen specifically because `JSONSerialization` loses member order, silently keeps only the last value for a duplicate key, and has no caller-controlled depth/size limits — this parser preserves source order, reports `.duplicateKey` as a real diagnostic, and enforces `StructuredDataLimits` (depth/node-count/string-length/number-length/source-size) while parsing. `XMLPlistParser` decodes XML property lists via `XMLParser` with external entity resolution disabled and a bounded pre-scan that outright rejects any `<!ENTITY` declaration (the actual defense against billion-laughs/XXE, since internal-entity expansion happens regardless of external-resolution settings). `BinaryPlistParser` is a from-scratch `bplist00` decoder (not `PropertyListSerialization`, for the same order/limit/diagnostic reasons) that bounds-checks every offset-table entry and object reference against the real buffer before use, detects and rejects cyclic object graphs instead of looping forever, and validates a declared object/element count against the remaining buffer size before ever allocating for it. All three feed the same `StructuredNode` tree (with `date`/`data` cases plists need that JSON does not); `StructuredSearch` provides bounded, iterative (never recursive, so a pathologically deep tree cannot overflow the call stack) case-insensitive key/value search, and `StructuredPath` renders a JavaScript-like accessor string for "copy key path". Invalid or rejected input is always `.invalid(StructuredDataDiagnostic)` with a specific, byte-offset-bearing message — never a silently-empty tree standing in for success.
- **PreviewUI and EditorUI integration** (headless-only, per this script's permanent UI-automation restriction): KodUI's `PreviewViewController` dispatches to `MarkdownPreviewViewController` (native `NSTextView`, never WebKit), `HTMLPreviewViewController`, `StructuredDataPreviewViewController`, or `ImagePreviewViewController`; EditorUI owns the Source/Preview tab toggle while the App shell supplies workspace trust, navigation, and confined-resource closures. Markdown's diagnostics/remote-image status banner collapses completely when unused, pinning the scroller directly to its container and leaving only normal responsive document padding. Remote Markdown images stay blocked until the per-document button is pressed, then use `BoundedRemoteFetcher` plus `ImageDecoder`; failures remain accessible textual states. Markdown local image references remain textual placeholders, while HTML local resources use the workspace-confined loader. The window toolbar's Source/Preview toggle and all existing navigation/history behavior are unchanged.
- **Hostile-input coverage** (`PreviewCoreTests`) exercises, for Markdown: `<script>`/event-handler/`javascript:`/`data:`/`file:`-scheme smuggling (including via HTML comments and malformed nested tags inside a script body), pathologically deep blockquotes/emphasis/many-block documents (bounded by `MarkdownLimits`, including a real quadratic-blowup regression guard for repeated unmatched emphasis delimiters), and oversized sources; for HTML: document recognition, CSP injection, disabled page scripting, workspace-relative resource resolution, and traversal confinement; for images: decompression-bomb-shaped forged PNG headers, corrupted magic bytes, truncated files, and per-limit dimension/pixel-count/frame-count rejections; for SVG: `<script>`/`<foreignObject>`/`<style>`/animation-element removal, external `href`/`url()` rejection, entity-declaration non-expansion, and unterminated-tag handling; for JSON/plist: duplicate keys, invalid UTF-8/escapes/surrogates, out-of-range binary-plist offsets and top-object indices, a hand-built cyclic binary-plist object reference, forged huge declared object counts, and depth/node/string/number limit violations — each verified to fail with a specific diagnostic or be safely stripped, never silently accepted or crashed on. `PreviewNoNetworkTests` registers a `URLProtocol` network spy proving Markdown/JSON/plist/image/SVG parsing and sanitizing never issue a network request, with a companion test proving the spy itself is load-bearing by showing the one intentional, explicit `BoundedRemoteFetcher` opt-in path *does* reach it. `PreviewCoreWorkspaceImmutabilityTests` SHA-256/size/mtime-fingerprints real Markdown/HTML/image/JSON/plist files (including hostile inputs) before and after the full preview pipeline runs and requires byte-for-byte equality. `PreviewCoreLatencyTests` cover parse/render/decode/search latency at Kod's own documented preview size limits.

Phase 11 hardens Kod into an accessible beta (SPEC 14/15): full `CodeViewport` NSAccessibility semantics and custom rotors, complete app-shell accessibility labels, keyboard/menu reachability, 300%-zoom/appearance support, a new `DiagnosticsCore` package, string localization infrastructure, and trust/privacy safeguards. No new UI-automation testing was added or is ever run by `Scripts/verify-phase`; a manual VoiceOver checklist covers what only a human can verify (see [docs/manual-voiceover-checklist.md](docs/manual-voiceover-checklist.md)).

- **`CodeViewport` accessibility** (`Packages/KodCore/Sources/CodeViewport/CodeViewportAccessibility.swift`): `CodeAccessibilityAnnotation` tags a UTF-8 byte range with a `.symbol`/`.diagnostic`/`.reference`/`.fold`/`.gitChange` kind and a human label; `applyAccessibilityAnnotations(_:)` feeds these in from the app layer (LSP symbols/diagnostics/references, fold state, Git changes) without touching the separate visual decoration-layer pipeline. `accessibilityChildren()` exposes one lightweight, line-number-keyed element per currently *visible* source line (virtualized, matching the rest of this codebase's rendering philosophy), each with a real on-screen `accessibilityFrame()`. `accessibilityCustomRotors()` returns one `NSAccessibilityCustomRotor` per populated annotation kind (Symbols/Diagnostics/References/Folds/Git Changes — never an empty rotor for an absent kind), each walking its annotations in document order via the real `NSAccessibilityCustomRotorItemSearchDelegate` contract. `accessibilityHitTest(_:)` maps a screen point to the corresponding line element; `accessibilityAttributedString(for:)` returns real theme-colored, fonted text for a UTF-16 `NSRange`, converted through a new `SourceSnapshot.globalUTF8Offset(forGlobalUTF16Offset:)` (the exact inverse of the existing `globalUTF16Offset(forUTF8Offset:)`) so AX clients can round-trip UTF-16 ranges back to the byte offsets `selectUTF8Range`/`text(inUTF8Range:)` require; `selectUTF16Range(_:)` wraps that round-trip for selection. Read-only state is exposed via `isAccessibilitySelectorAllowed`/`accessibilityRoleDescription`/`accessibilityHelp` (selection/copy stay allowed; value-mutation does not) rather than a fabricated "editable" flag.
- **App-shell accessibility**: Explorer rows, tabs (name/pinned/preview/dirty state, distinctly-labeled close buttons), the active split group, Problems/Search/Source Control panel rows, LSP state/settings controls, diff/blame markers and annotations, and every preview's controls (zoom, transparency, animation pause, Source/Preview toggle, remote-image opt-in) all expose real accessibility labels/values reflecting current state — severities, change kinds, and LSP states are always announced as text, never by color alone.
- **Keyboard-command registry** (`App/KodApp/Commands/KeyboardCommandRegistry.swift`): a plain `KeyboardCommand` model built by recursively flattening the *real* `NSMenu` tree `AppDelegate` constructs (`AppDelegate.buildMainMenu()`, extracted as a testable, side-effect-free function), so the registry can never drift from the actual, shipping menu — it is validated against production menu construction, not a speculative parallel list. Every primary open/search/navigate/diagnose/diff/preview command is reachable both via its keyboard shortcut and a real, enabled native menu item.
- **Zoom and appearance**: `FontSettings.sizeRange` was widened to `8...48` (comfortably covering 300% of Kod's 13pt default) with a corresponding gutter-width fix so the line-number gutter grows with digit count instead of clipping at large sizes/line counts. Kod follows macOS appearance automatically with Kod Light or Kod Dark, and Reduce Motion (`NSWorkspace.shared.accessibilityDisplayShouldReduceMotion`) is honored by Kod's own transitions.
- **`DiagnosticsCore`** (`Packages/KodCore/Sources/DiagnosticsCore/`) provides structured, category-tagged diagnostics, bounded event storage, deterministic redaction, opt-in crash reporting, and human-readable support bundles; persistence and quarantine mechanics come from `SettingsCore`. `NetworkAttribution` names app updates, remote Markdown resources, and crash reports explicitly.
- **Trust and privacy UI**: a persistent status-bar indicator exposes the current trust state in its tooltip and prompts before allowing or revoking trust; revocation is immediately effective and stops running language servers for that workspace. Language details expose only server status, the effective Command, and conditional installation guidance. Structured runtime diagnostics continue to use `DiagnosticsCore` internally but are not exposed as a Settings destination.
- **Localization**: `App/KodApp/Resources/Localizable.xcstrings`, a real Xcode String Catalog (English-only source language — SPEC 14 requires the localization *infrastructure*, not fabricated translations, from the first release), wired into the `Kod` target's build resources. `App/KodApp/Localization/Localized.swift` wraps `String(localized:comment:)` for AppKit call sites (SwiftUI `Text("...")` literals already auto-resolve against the catalog via `LocalizedStringKey`, so those were left as-is). Every Kod-owned user-facing string in `App/KodApp/` — menu titles, control titles/labels, accessibility labels/values/hints, alert/panel copy, status/error banner text — was migrated, each with a translator-facing `comment:`. `UserFacingStringAuditTests` scans Swift files recursively below `App/KodApp` for hardcoded literals reaching a defined set of user-facing sink patterns (excluding `.accessibilityIdentifier`, log calls, and other non-user-facing carve-outs) and fails on any new violation, with a regression test proving the scanner actually catches a deliberately reintroduced one. `PseudolocalizationTests` applies a deterministic, real length-expanding transform to clipping-prone model strings (tab labels, button titles, status text) and measures them through real AppKit string-sizing APIs (`NSAttributedString`/`NSString` sizing) to prove the measurement path is genuinely exercised, not just asserting a string is non-empty.

Automated coverage: `CodeViewportAccessibilityTests` (roles/labels/values/UTF-16 range round-trips/hit-testing/rotor item models/read-only-selector gating), `SettingsCoreTests` (adapters, typed failures, envelopes/migrations, validation, observation cancellation, and bounded quarantine), `DiagnosticsCoreTests` (bounded-log capacity/drop tracking, deterministic redaction, opt-in crash-report gating with a recording transport, support-bundle manifest/redaction/write round-trips), corrupt-metadata migration tests in `FontCoreTests`/`ThemeCoreTests`/`WorkspaceCoreTests`/`LanguageAdaptersTests`, KodUI's `AppearanceCenterTests`, `EditorGroupTabAccessibilityTests`, preview/Git controller tests, and `KodAppTests`' `KeyboardCommandRegistryTests`, `WorkspaceViewControllerTrustControlTests`, `PseudolocalizationTests`, and `UserFacingStringAuditTests`. Phase 12 qualifies Kod for release (SPEC 16.2/17 M4): "Every acceptance criterion in section 16.2 passes" wherever this environment can produce real evidence for it, and every criterion it cannot (production signing/notarization credentials, physical Intel/clean-Mac hardware, a human running VoiceOver) is explicitly, individually marked as such — never silently skipped or fabricated.

- **Acceptance-evidence system** (`Scripts/acceptance-evidence/`): maps all 15 SPEC 16.2 criteria to the concrete test suite(s)/command(s) that produce evidence for each, runs them, and writes `Artifacts/acceptance-evidence/acceptance-evidence.{json,md}` with one of six honest statuses per criterion — `passed`, `failed`, `skipped` (e.g. the opt-in 100k-file scale gate), `manual_required` (VoiceOver), `credential_gated` (real signing/notarization), or `hardware_gated` (a real clean Mac/Intel machine). `Scripts/verify-phase 12` runs it automatically; pass `--run-xcodebuild` for the (slower) KodAppTests-backed criteria too.
