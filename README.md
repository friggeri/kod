# Kod

Kod is a native, strictly read-only macOS code viewer. The product and technical requirements are in [SPEC.md](SPEC.md). Privacy details are in [docs/privacy.md](docs/privacy.md); support/troubleshooting guidance is in [docs/support.md](docs/support.md); the manual VoiceOver release checklist (never run by any automated agent) is in [docs/manual-voiceover-checklist.md](docs/manual-voiceover-checklist.md); release packaging/signing/notarization is in [Scripts/release/README.md](Scripts/release/README.md); Intel/x86_64 compatibility evidence and its limits are in [docs/intel-compatibility-report.md](docs/intel-compatibility-report.md).

## Requirements

- macOS 14 or later
- Xcode 26 or later
- Swift 6

## Build and test

Run the cumulative verification gate for the current implementation phase:

```sh
Scripts/verify-phase 12
```

Or open `Kod.xcodeproj` and run the `Kod` scheme.

Set `KOD_RUN_SCALE_TESTS=1` to additionally run the 100,000-file discovery scale gate (skipped by default; it generates a large local fixture and is slow).

Phase 7 additionally requires pinned real TypeScript/JavaScript, HTML, CSS, Python, and Rust language servers for `LanguageAdaptersTests`'s real integration tests; run `Scripts/vendor-test-language-servers/setup.sh` once (or after a clean checkout) to install them. `Scripts/verify-phase 7` (and 8) checks for them up front and fails fast with that exact command if they're missing.

Phase 2 adds one-root workspaces, progressive repository discovery, a lazy Explorer, workspace trust, recent roots, and path-aware Quick Open on top of the immutable source viewer.

Phase 3 adds a complete plain-text viewing workflow: preview and pinned tabs with reordering, nested horizontal/vertical split editor groups with an independently active group, per-group Back/Forward navigation that restores file, selection, and viewport, Find in File (plain, case-sensitive, whole-word, and regex modes) with result navigation, Go to Line, a word-wrap toggle (default off, without weakening the 10 MB fast path), a Command Palette, native menu/shortcut wiring, and external metadata persistence for window/split/tab/navigation/selection/scroll state that never writes into the opened workspace.

Phase 4 adds real syntax and visual customization on top of the plain-text viewer:

- **`SyntaxCore`**: pinned, compiled-in Tree-sitter grammars (via vendored `CTreeSitter*` packages; see [THIRD_PARTY_NOTICES.md](THIRD_PARTY_NOTICES.md)) for Swift, TypeScript, JavaScript, HTML, CSS, Python, and Rust — no runtime grammar-extension mechanism. Snapshot-versioned, viewport-prioritized highlight captures feed a versioned decoration compositor with layers for lexical syntax, and slots prepared for future semantic tokens, search, and diagnostics; results for a superseded snapshot are discarded rather than painted.
- **`CodeViewport`** now paints real lexical syntax colors (first paint stays plain-text and independent of parsing), structural code folding, indentation guides, matching-bracket highlighting/navigation, and sticky scope headers, all through the existing source/visual mapping and word-wrap machinery.
- **`ThemeCore`**: a versioned native theme schema, PVC-derived Kod Light and Kod Dark defaults, dedicated high-contrast light and dark themes with enhanced WCAG contrast checks, and VS Code color-theme JSON import (`colors`/`tokenColors`/`semanticTokenColors`) with an explicit unsupported-field report and TextMate-scope precedence resolution.
- **`FontCore`**: installed monospaced font discovery, and settings for family, size, weight, ligatures, line height, letter spacing, and ordered fallback families, applied live and persisted outside any workspace.
- A native Settings window (`Kod > Settings...`, ⌘,) for theme selection/import and font configuration, plus `Toggle Fold` and `Go to Matching Bracket` menu commands.

See `Scripts/vendor-tree-sitter/` for the exact pinned commits used to vendor the Tree-sitter runtime and grammars, and how to refresh them.

Phase 5 adds workspace search and live filesystem awareness:

- **`SearchCore`**: a bundled, version-pinned, licensed ripgrep-compatible engine (`rg` 14.1.1; see [THIRD_PARTY_NOTICES.md](THIRD_PARTY_NOTICES.md) and `Scripts/vendor-ripgrep/`) for both Apple silicon and Intel, launched only via an absolute executable `URL` and fixed argument arrays — never a shell string or `PATH` lookup. Streaming, bounded, incremental JSON output parsing yields UTF-8-safe match ranges; every query is cancellable and a new query supersedes (and terminates) any query already running; explicit result limits mark truncation instead of pretending a capped search finished; case, whole-word, regex, include/exclude globs, hidden files, and ignored files are all supported, with `.gitignore`/`.ignore` respected even outside an actual Git repository and `.git` always excluded regardless of other options.
- A **Search sidebar** in the workspace window (toggle with the Explorer/Search segmented control, or Command-Shift-F / the Command Palette) streams results grouped by file as they arrive; selecting a match opens it in the active editor group with the match selected.
- **FSEvents-based live updates**: workspace changes are coalesced across short write bursts, then applied incrementally — the Explorer tree and filename index update per changed path (using the same nested-`.gitignore`-aware classification as full discovery, not a full rescan) unless an ignore-defining file itself changed, in which case Kod safely falls back to a full rescan. Externally modified open files reload automatically into a new, version-bumped, immutable `SourceSnapshot`, preserving the nearest selection, viewport line, and code folds via a content-addressed reconciler. A deleted or moved open file becomes an explicit tombstone tab (visible until closed or the path becomes valid again) instead of silently disappearing or continuing to show stale content.
- Stale syntax, search, and reload results are rejected by snapshot/query version throughout, so a slow in-flight computation for a superseded snapshot or query can never overwrite what the user is currently looking at.

See `Scripts/vendor-ripgrep/` for the exact pinned commit, source checksum, and reproducible build script used to vendor the search engine, and how to refresh it.

Phase 6 adds a Swift LSP vertical slice on top of the syntax/search foundation:

- **`LanguageClient`**: a from-scratch JSON-RPC 2.0 / LSP 3.17 client — bounded `Content-Length` framing tolerant of arbitrarily fragmented reads, typed request/notification/response models for every capability implemented below, per-request timeouts, `$/cancelRequest` support (including automatic cancellation when Kod's own calling `Task` is cancelled), work-done progress (driving an explicit `indexing` state), and bounded rotating stderr capture. One dedicated actor owns each connection/process; every executable is launched via an absolute, pre-resolved `URL` with a fixed argument array — never a shell string or `PATH` lookup. A crashed server auto-restarts up to three times in five minutes (re-synchronizing every previously-open document via `didOpen` after each restart) before Kod disables it and requires a manual Restart.
- Kod's advertised capabilities during `initialize` are strictly read-only: no `workspace.applyEdit`, rename, code actions, formatting, `workspace/executeCommand`, or file operations, and no dynamic registration for anything Kod implements. Every outgoing request is drawn from a fixed allow-list (there is no generic "send any request" escape hatch), and any server-initiated `client/registerCapability`/`workspace/applyEdit` is rejected with an explicit JSON-RPC error rather than silently accepted or ignored.
- **`SourceKitLSPDiscovery`** resolves Swift's language server exclusively through `xcrun --find sourcekit-lsp` at its fixed absolute location — never a shell string or cached guess — with one process started lazily per trusted Swift workspace, only after `WorkspaceTrustStore` confirms trust.
- **`SwiftWorkspaceLanguageService`** synchronizes each open Swift document as an immutable, versioned `SourceSnapshot` (`didOpen`/`didChange`/`didClose`), negotiates UTF-8 positions where a server supports them and otherwise maintains the existing tested UTF-16 mapping, and validates every returned URI/range/snapshot version before use — a stale or out-of-bounds response is discarded rather than shown. It implements hover, definition, references, document/workspace symbols, push and (capability-gated) pull diagnostics, and full semantic tokens, which feed the existing decoration compositor's `.semantic` layer above lexical highlighting.
- The workspace sidebar gains **Problems** and **Symbols** surfaces (alongside Explorer/Search) plus a server-state indicator (Missing/Starting/Indexing/Ready/Busy/Stopped/Crashed/Disabled) with a manual Restart action; syntax highlighting and text search remain fully usable when SourceKit-LSP is absent, still starting, or has crashed.
- A deterministic, scenario-driven **`FakeLanguageServer`** stdio fixture (built as a separate executable target, reusing `LanguageClient`'s own framing/encoding code) exercises fragmented frames, malformed/oversized payloads, cancellation, timeouts, work-done progress, bounded stderr, crashes and restart, adversarial dynamic-registration/`applyEdit` attempts, and invalid/stale ranges — all headless, no real language server involved.
- Real, headless `sourcekit-lsp` integration tests run against a small checked-in fixture Swift package (`Packages/KodCore/Tests/LanguageClientTests/Fixtures/SourceKitLSPFixture`), with a normalized recorded transcript of one session checked in alongside them for reference. **Known, documented limitation for the SourceKit-LSP shipped with this Xcode toolchain:** it does not declare `positionEncoding` (Kod correctly falls back to UTF-16) and does not advertise `diagnosticProvider` even though it implements pull diagnostics informally — Kod capability-gates pull diagnostics off for this server and relies on push (`textDocument/publishDiagnostics`) instead, exactly as SPEC 6.4's "publish and pull diagnostics" wording anticipates for servers where only one is applicable.

Phase 7 completes the read-only LSP product across every launch language:

- **Complete capability surface.** `LanguageClient` now models and capability-gates declaration, type definition, implementation, document highlight, workspace symbols, pull diagnostics, inlay hints, explicit signature help, call hierarchy, type hierarchy, folding ranges, selection ranges, and safe document links, alongside Phase 6's hover/definition/references/document symbols/semantic tokens/push diagnostics. Every result is validated the same way Phase 6's were: cross-file navigation targets (definition/declaration/type-definition/implementation/references/hierarchy items) are validated structurally (absolute `file://` URI, non-negative, non-inverted range); same-document results (hover, document highlight, folding/selection ranges, inlay hints, document link ranges) are validated against the requesting snapshot's actual UTF-8 bounds; an out-of-bounds or malformed result is discarded, never shown. Document links additionally reject any non-`file`/`https`/`http` target (e.g. a `command:` URI some servers use to trigger client-side actions) outright — `SafeDocumentLink.validating(_:)` — since Kod must never treat a server-supplied link as something to execute.
- **Dynamic registration for read-only capabilities.** `LanguageServerConnection` now inspects a `client/registerCapability` batch and accepts it only if every registered method is one Kod already knows how to use read-only; a batch containing even one mutating or unrecognized method is rejected in full (no partial acceptance), and `client/unregisterCapability` is always accepted (removing a registration can never grant a new capability). This lets a server that only advertises certain read-only features dynamically (rather than in `initialize`) still work, while the "reject every mutating registration" guarantee from Phase 6 is unchanged.
- **`LanguageWorkspaceService`**, a new language-agnostic engine implementing the complete capability surface above (lifecycle, document sync, capability gating, validation) shared by every adapter. `SwiftWorkspaceLanguageService` is now a thin wrapper around it — its own public API and error type are unchanged from Phase 6 — so Swift and every other language share one implementation rather than five parallel ones.
- **`LanguageAdapters`**, a new package with a typed `LanguageAdapter` protocol and a deterministic discovery engine (`LanguageServerDiscoveryEngine`) implementing SPEC 6.5's exact precedence: an explicit per-workspace override stored outside the repository (`LanguageServerOverrideStore`, `UserDefaults`-backed like `WorkspaceTrustStore`), an explicit global override, language-specific system discovery (`xcrun --find sourcekit-lsp`, `rustup which rust-analyzer`), a captured login-shell `PATH` (`LoginShellPathCapture`, since GUI apps don't inherit a shell rc file's `PATH`), and common package-manager install locations — Kod-managed installation (the sixth and final tier) is Phase 8 work. Every tier only ever launches a fixed, absolute executable with a fixed argument array or reads a fixed list of directories; nothing here evaluates a shell string or a repository-provided command. Every resolved executable reports its absolute path, best-effort version (from running the resolved executable itself with a fixed `--version`-style argument), precedence tier, and launch arguments before first use.
- **Adapters for TypeScript/JavaScript** (`typescript-language-server` + `typescript`), **HTML and CSS** (`vscode-html-language-server`/`vscode-css-language-server` from `vscode-langservers-extracted`), **Python** (Pyright's `pyright-langserver`), and **Rust** (`rust-analyzer`), alongside the preserved Swift adapter (`SwiftAdapter`, still exclusively `xcrun --find sourcekit-lsp` as its language-specific tier). Manual executable configuration (a workspace or global override) works today, before any Kod-managed install exists.
- **`MultiLanguageServicesCoordinator`** owns one `LanguageWorkspaceService` per (workspace, non-Swift adapter) pair in the app, lazily started the same way `LanguageServicesCoordinator` starts Swift's — Swift itself keeps going through the Phase 6 `LanguageServicesCoordinator`/`SwiftWorkspaceLanguageService` pipeline unchanged, so a Swift workspace never launches a second, redundant SourceKit-LSP process.
- **Peek Definition and Call Hierarchy** are real, reachable Command Palette commands for the active Swift document: `PeekViewController` shows a durable, always-replaced-wholesale list of validated navigation targets (never a raw, unvalidated server response); `HierarchyViewController` is a lazily-expanding, mode-switchable (Callers/Callees, or Supertypes/Subtypes for type hierarchy) outline over `ValidatedHierarchyItem`, reusable for both call and type hierarchy. Both are presented as sheets (`PeekPanelController`/`HierarchyPanelController`) and validated only through headless controller tests — no UI automation.
- **`FakeLanguageServer`** gained scenarios for every new capability, a `capability-absent` scenario (proving Kod hides/disables a feature rather than erroring when a server never advertises it), read-only-vs-mixed-batch dynamic-registration scenarios, and an unsafe-`command:`-URI document-link scenario.
- **Real, headless integration tests** run against pinned versions of every new server (`typescript-language-server` 4.3.4, `vscode-langservers-extracted` 4.10.0, Pyright 1.1.407, and `rust-analyzer` via a pinned `rustup` component) against small checked-in fixtures (`Packages/KodCore/Tests/LanguageAdaptersTests/Fixtures`) — see `Scripts/vendor-test-language-servers/setup.sh` to provision them and `Scripts/vendor-test-language-servers/compatibility-matrix.md` for exactly which capabilities each pinned server advertises and any interop findings (including a real LSP-interop bug this phase fixed: `vscode-css-language-server` omits `DocumentSymbol.children` entirely for leaf symbols, which is valid per LSP 3.17 but broke Kod's original, stricter decoder). None of these servers are vendored, bundled, or shipped — Kod-managed installation is Phase 8 work; see `THIRD_PARTY_NOTICES.md` for their licenses.
- Repository-immutability and process-spy coverage extends to every adapter: each real-server integration test checksums its fixture file before and after exercising the adapter, and the generic `LanguageWorkspaceService` (shared by all five non-Swift adapters) has its own crash-loop/restart, capability-absence, and invalid-range-discard tests independent of `SwiftWorkspaceLanguageService`'s wrapper.

`Scripts/verify-phase` never launches `KodAppUITests`, `Kod.app`, `XCUIApplication`, or any GUI/AppleScript automation — this is a permanent restriction, not one later phases may relax.

Phase 8 adds secure Kod-managed language-server installation, the sixth and final SPEC 6.5 discovery tier:

- **`ManagedLanguageServers`**, a new package holding the entire subsystem: a versioned, `Codable` catalog model (`ManagedServerCatalog`/`ManagedServerCatalogEntry`/`ManagedServerArtifact`, with per-architecture artifacts, exact SHA-256 digests, archive layout/executable-path declarations, revocation, minimum-Kod-version gating, and optional private-runtime requirements); Ed25519 (Curve25519, via Apple's `CryptoKit`) catalog signing/verification (`CatalogSigner`/`CatalogVerifier`/`CatalogTrustRoot`) that never reads a single catalog entry before the signature over its canonical bytes checks out, with explicit key-rotation windows and independent per-entry and per-digest revocation; a from-scratch, dependency-free gzip (`GzipCodec`, built on Apple's `Compression` framework) and USTAR tar (`TarReader`/`TarWriter`) codec; and `SecureArchiveExtractor`, which rejects path traversal, absolute paths, symlinks, hardlinks, device/special files, duplicate and case-folding path collisions, decompression bombs (via bounded streaming inflate, never "inflate fully then check"), and any archive whose final file set doesn't exactly match the catalog's declared layout.
- **`ManagedInstallController`**, an actor orchestrating the full lifecycle under `~/Library/Application Support/Kod/LanguageServers` (never the workspace): explicit per-version/architecture consent before any network access, a bounded/cancellable HTTPS (or loopback-`http`, for tests only — see `ManagedInstallController`'s `isSecureArtifactURL`) download (`BoundedDownloader`), staged extraction into a fresh temporary directory, digest verification, atomic activation via a write-temp-then-`rename()` pointer file (`ActiveVersionStore`), upgrade, rollback, removal, and interrupted-operation recovery (`recoverInterruptedOperations`) that cleans up any staging/download leftovers from a crash mid-install. Concurrent installs for the same server are coalesced onto one in-process `Task` and additionally serialized by a cross-process `flock`-backed `InstallLock`.
- **`ManagedInstallDiscoverySource`** (in `LanguageAdapters`) bridges an active managed install into a `DiscoveredExecutable` with `source: .managedInstall` — the sixth and final tier `LanguageServerDiscoveryEngine.resolve` now supports, wired into the TypeScript/JavaScript, HTML, CSS, and Rust adapters (Python's Pyright too); Swift/SourceKit-LSP deliberately has no managed-install tier, staying guided-Xcode-only per SPEC 6.5.
- **`ManagedInstallCoordinator`/`ManagedInstallStatusModel`** (in the `Kod` app target) expose per-server provenance/version/architecture/path and setup/install/update/rollback/remove state for a setup UI to bind to — validated only through headless `KodAppTests`, never through `KodAppUITests`/`XCUIApplication`.
- **Hostile-input coverage** (`ManagedLanguageServersTests`) exercises every attack above individually, plus a decompression bomb, a smuggled unexpected executable, revoked catalogs/entries/artifact digests, tampered/forged catalog signatures, expired signing-key windows, wrong-architecture artifacts, digest mismatches, cancellation cleanup, concurrent-install coalescing, and full workspace immutability — entirely offline, against a signed fixture catalog (`FixtureCatalog`, signed with a fixed, clearly-labeled, non-secret test key) and fixture `tar.gz` artifacts built from this repository's own `FakeLanguageServer` executable, plus a minimal loopback-only HTTP server (`LocalHTTPTestServer`) for real download-mechanics coverage. `ManagedInstallLifecycleTests.testInstallThenLaunchRealProcess` installs a fixture server end to end and then genuinely launches it, sending a real `initialize` request over real stdio LSP framing.
- **`ManagedCatalogTool`**, a small release/test-only executable (`swift build --product ManagedCatalogTool`) for generating an Ed25519 key pair, signing a catalog JSON file, and verifying a signed envelope — see `Scripts/managed-install-signing/README.md` for the full key-generation/rotation/revocation/reproducible-artifact-generation process and this environment's explicit release-provisioning gap (no real, notarized production signing key exists here; `CatalogTrustRoot.production` is intentionally empty until one does).
- See `Scripts/managed-install-signing/ARCHITECTURE_MATRIX.md` for the Apple-silicon-first/Intel-best-effort matrix per managed server, and `THIRD_PARTY_NOTICES.md` for the upstream projects (`typescript-language-server`, `vscode-langservers-extracted`, Pyright, `rust-analyzer`, Node.js) a real release's catalog would reference — none of their binaries are vendored into this repository.

Phase 9 adds hardened, read-only Git context (SPEC 9):

- **`GitCore`**, a new package invoking only an explicitly resolved, absolute Git executable (`GitExecutableLocator`, a fixed candidate list — Homebrew's Apple-silicon/Intel prefixes, then Apple's own Xcode Command Line Tools `/usr/bin/git` — never a `PATH`/shell lookup) with a fixed global argument prefix and minimal explicit environment (`GitInvocationHardening`): `--no-pager --no-optional-locks --no-replace-objects`, `GIT_OPTIONAL_LOCKS=0`, `GIT_TERMINAL_PROMPT=0`/a no-op `GIT_ASKPASS`/`GIT_SSH_COMMAND`, disabled hooks (`core.hooksPath=/dev/null`), fsmonitor (`core.fsmonitor=false`), external diff/textconv, color, and credential helpers, and `protocol.allow=never` (defense in depth; Kod never fetches or touches a remote). `GitReadOnlyCommand` is an exhaustive allow-list of read-only subcommands (`status`, `diff`, `blame`, `rev-parse`, `symbolic-ref`, `cat-file`, `ls-files`, `log`, `show`) — mirroring `LanguageClientOutboundMethod`'s allow-list discipline — so a mutating invocation is structurally impossible to construct from `GitCore`'s own code. `GitProcessRunner` (modeled directly on `SearchCore`'s `RipgrepProcessSession`) bounds stdout/stderr, enforces a timeout, and guarantees the child process is terminated on cancellation.
- **`GitRepositoryLocator`** detects a repository/worktree's root, its own (possibly linked-worktree-private) git-directory vs. the shared common directory, bare-repository state, and current branch or detached-`HEAD` commit id, via one combined `rev-parse` call plus `symbolic-ref`.
- **`GitStatusParser`** parses `git status --porcelain=v2 -z` (ordinary, rename/copy, unmerged, untracked, and ignored record shapes) into `GitStatusEntry`/`GitStatusSnapshot`, grouped into staged/unstaged/untracked/ignored/conflicted/renamed exactly as SPEC 9.1 asks — `-z` NUL-separation means every path (arbitrary bytes, Unicode, tabs) round-trips without Git's usual C-style quoting/escaping ever entering the picture.
- **`GitDiffParser`/`GitDiffService`** compute a file's diff against whichever of `HEAD`/index/working-tree applies (`workingTreeVsIndex`, `indexVsHead`, `workingTreeVsHead`), via a two-step, always-read-only invocation: a NUL-separated `--raw` call resolves exact add/delete/modify/rename/copy identity and old/new mode with no path-quoting ambiguity, then a patch call restricted (with `--`) to exactly the resolved path(s) produces hunks — passing both the old and new path together is what makes Git's own rename pairing work within a single pathspec-restricted call. Untracked files use `git diff --no-index` against `/dev/null` (the one invocation allowed to exit `1` as a normal "files differ" outcome). `GitSideBySideProjection` pairs each hunk's removed/added runs into side-by-side rows.
- **`GitBlameParser`/`GitBlameService`** parse `git blame --porcelain`: per-commit author/committer name/email/time/timezone/summary (cached the first time a commit id appears anywhere in the stream, exactly matching Git's own porcelain-omission behavior for repeated, even non-consecutive, occurrences), original/final line numbers, boundary commits, the synthetic all-zero "Not Committed Yet" uncommitted-line commit, and `previous`/`filename` rename-following metadata.
- **`GitRepositoryStateIdentity`/`GitResultCache`** key cached status/diff/blame results off `HEAD` + a plain `stat()` of the per-worktree index file + a generation counter `GitContext` bumps from the workspace's existing `WorkspaceFileWatcher` FSEvents pipeline — invalidating Kod's own in-memory cache only, never writing anything to `.git` or the working tree.
- **`GitContext`**, the single facade type App code holds per workspace: resolves the repository once, then serves cached/fresh status/diff/blame.
- **App integration** (headless-only, per this script's permanent UI-automation restriction): `GitWorkspaceCoordinator` owns a workspace's optional `GitContext` and Explorer badge classification; a new "Source Control" sidebar tab (`SourceControlSidebarViewController`) groups files exactly as `GitStatusSnapshot` does; `GitDiffViewController`/`GitDiffPanelController` render unified and side-by-side diffs; `GitBlameViewController`/`GitBlamePanelController` render per-line blame plus a commit-metadata popover; a new `.gitChange` `DecorationLayerKind` (`GitLineDecorationBuilder`/`GitDecorationLayerBuilder`) integrates inline added/modified gutter tints through the same versioned `DecorationCompositor` pipeline syntax highlighting/search/diagnostics already use, using the existing `GitDecorationColors` theme tokens.
- **Deterministic fixtures** (`GitFixtureBuilder`, fixed `GIT_AUTHOR_DATE`/`GIT_COMMITTER_DATE`/identity/`GIT_CONFIG_GLOBAL=/dev/null`) build real repositories with commits, staged/unstaged edits, adds/deletes/renames/copies, real merge conflicts, ignored/untracked files, binary content, and multi-author/multi-timezone blame history; parsed Kod models are compared against independently-invoked real Git output (`GitStatusParserTests`/`GitDiffParserTests`/`GitBlameParserTests`).
- **`GitProcessSpy`**, a small executable standing in for the resolved Git binary in tests: it logs every invocation's exact argv/env to a file, then re-execs the real Git binary so functional behavior is unaffected while `GitProcessInvocationSpyTests` independently asserts the exact executable/arguments/environment used and the absence of any mutating, network, helper, or hook subcommand.
- **`GitImmutabilityTests`** take a SHA-256 (content + mtime + type) manifest of both the working tree and the entire `.git` directory before and after every workflow (status/diff/blame/repository-location, including with a deliberately backdated index to provoke Git's normal opportunistic index-refresh write-back) and require byte-for-byte equality — plus a regression guard that proves an *unhardened* `git status` really would have rewritten `.git/index`, so the assertion is demonstrably load-bearing rather than vacuous.
- **`GitPerformanceCancellationCacheTests`** cover status/diff/blame latency budgets, `GitProcessRunner` cancellation and timeout termination, bounded/truncated output, and `GitContext`/`GitResultCache` identity-based cache hits and invalidation.

Phase 10 adds safe built-in previews (SPEC 10):

- **`PreviewCore`**, a new, dependency-free package (only Foundation/ImageIO/CoreGraphics/UniformTypeIdentifiers and this repository's own `SourceModel`/`SyntaxCore`/`ThemeCore` — no third-party libraries) holding the entire subsystem. **`PreviewContentDetector`** dispatches by validated content (magic bytes for images; a `bplist00` signature or a recognized `UTType` for JSON/plist; content, never a path extension alone, decides) to one of `PreviewKind.markdown`/`.image(ImageFormat)`/`.structuredData`/`.none`.
- **Markdown**: `MarkdownParser` is a from-scratch, line-oriented recursive-descent parser (not a spec-conformance-tested CommonMark implementation, but exact on every security-relevant behavior) covering headings (ATX and setext), paragraphs with soft/hard breaks, blockquotes (including lazy continuation and nesting), ordered/unordered/task lists, fenced and indented code blocks, thematic breaks, GFM tables with alignment, emphasis/strong/strikethrough/code spans, links/images/autolinks, and character-entity decoding. `MarkdownDestination` classifies every link/image/autolink destination (`local`, `http`, `https`, `mailto`, or `unsafeOrUnrecognized`) so link/image policy is enforced from data, not string-sniffed ad hoc. Raw HTML (block or inline) is always routed through `MarkdownHTMLSanitizer`, itself preceded by `DangerousElementStripper` — a whole-document, case-insensitive textual pre-pass that removes `<script>`/`<style>`/`<iframe>`/`<object>`/`<embed>`/`<template>`/`<noscript>`/`<form>` (open tag through matching close tag, or to end-of-document if unterminated) *before* any block/inline boundary is even determined, which is what actually defeats smuggling a script body through Markdown's "each raw-HTML tag is its own independent inline span" model. The remaining allow-listed formatting tags have their attributes filtered (event handlers, `javascript:`/unsafe-scheme `href`/`src`, inline `style` all stripped); an orphaned closing tag can only survive if its name is itself on the allow-list, never based on assuming a same-call matching open tag. `MarkdownRenderer` (async, since it goes through the real `SyntaxEngine` actor) turns a parsed document into a `MarkdownRenderDocument` of styled runs, syntax-highlighting fenced code through the *exact same* `SourceModel`/`SyntaxCore`/`ThemeCore` pipeline `CodeViewport` uses for whole files — no second source-rendering path. `MarkdownResourcePolicy` blocks remote images by default and requires an explicit, non-persisted per-document opt-in (`BoundedRemoteFetcher`, HTTPS-only, size/timeout-bounded, and never called except from that opt-in) and gates non-local link navigation behind confirmation in an untrusted workspace.
- **Images**: `ImageDecoder` decodes PNG/JPEG/GIF/HEIC/TIFF via ImageIO with every `ImageDecodeLimits` check (source size, per-frame dimension, per-frame pixel count, frame count, and a running total decoded-byte budget) applied against each frame's *declared* properties — read via `CGImageSourceCopyPropertiesAtIndex`, which parses only the container header — strictly before any pixel buffer is decoded, so a decompression bomb's true cost is caught without ever inflating it. SVG is deliberately never handed to ImageIO: `SVGSanitizer` (built on a from-scratch `LenientXMLTokenizer`) is a real allow-list sanitizer — only pure vector-drawing elements/attributes survive; `<script>`/`<foreignObject>`/`<style>`/animation elements are removed outright (via the same textual `DangerousElementStripper` pre-pass plus token-level filtering), external `href`/`xlink:href`/`url()` references are rejected unless a same-document `#fragment` or an inline `data:image/...` URI, and DOCTYPE/ENTITY declarations are never processed at all (the tokenizer skips markup declarations wholesale), which is what actually stops "billion laughs"-style entity-expansion and XXE attempts rather than merely disabling external-entity resolution. `SVGDocumentLoader` reports intrinsic size (from `width`/`height` or `viewBox`) alongside the sanitized XML.
- **JSON and property lists**: `JSONParser` is a hand-rolled, strict RFC 8259 parser (not `JSONSerialization`) chosen specifically because `JSONSerialization` loses member order, silently keeps only the last value for a duplicate key, and has no caller-controlled depth/size limits — this parser preserves source order, reports `.duplicateKey` as a real diagnostic, and enforces `StructuredDataLimits` (depth/node-count/string-length/number-length/source-size) while parsing. `XMLPlistParser` decodes XML property lists via `XMLParser` with external entity resolution disabled and a bounded pre-scan that outright rejects any `<!ENTITY` declaration (the actual defense against billion-laughs/XXE, since internal-entity expansion happens regardless of external-resolution settings). `BinaryPlistParser` is a from-scratch `bplist00` decoder (not `PropertyListSerialization`, for the same order/limit/diagnostic reasons) that bounds-checks every offset-table entry and object reference against the real buffer before use, detects and rejects cyclic object graphs instead of looping forever, and validates a declared object/element count against the remaining buffer size before ever allocating for it. All three feed the same `StructuredNode` tree (with `date`/`data` cases plists need that JSON does not); `StructuredSearch` provides bounded, iterative (never recursive, so a pathologically deep tree cannot overflow the call stack) case-insensitive key/value search, and `StructuredPath` renders a JavaScript-like accessor string for "copy key path". Invalid or rejected input is always `.invalid(StructuredDataDiagnostic)` with a specific, byte-offset-bearing message — never a silently-empty tree standing in for success.
- **App integration** (headless-only, per this script's permanent UI-automation restriction): `PreviewViewController` dispatches to `MarkdownPreviewViewController` (a native `NSTextView`-based renderer — no WebKit anywhere in this pipeline — with link-click confirmation and the remote-image opt-in control), `StructuredDataPreviewViewController` (an `NSOutlineView` tree with search and copy-value/copy-key-path, falling back to a visible parse diagnostic for invalid data rather than a blank tree), or `ImagePreviewViewController` (fit/actual-size/zoom, a transparency checkerboard toggle, safe frame-timed GIF animation with a pause control, and a metadata panel). `EditorGroupViewController` gained a Source/Preview toggle: a newly-opened Markdown/JSON/plist tab defaults into its built-in preview while its `CodeDocumentViewController` keeps loading and working exactly as before underneath, so toggling to "Source" never reloads anything and Find/Go-to-Line/word-wrap/navigation history are completely unaffected. Since a raster image is not valid UTF-8 text, `SourceSnapshotLoader` correctly refuses to load one at all (SPEC 11.4); rather than the previous silent no-op, `EditorGroupViewController`/`WorkspaceViewController` now recover from exactly that failure by reading the file's raw bytes (`loadRawData`, independent of any text-decoding requirement) and, only if they are a recognized image format, opening a preview-only tab with no `CodeDocumentViewController` at all (there is no meaningful "Source" view for binary image bytes).
- **Hostile-input coverage** (`PreviewCoreTests`) exercises, for Markdown: `<script>`/event-handler/`javascript:`/`data:`/`file:`-scheme smuggling (including via HTML comments and malformed nested tags inside a script body), pathologically deep blockquotes/emphasis/many-block documents (bounded by `MarkdownLimits`, including a real quadratic-blowup regression guard for repeated unmatched emphasis delimiters), and oversized sources; for images: decompression-bomb-shaped forged PNG headers, corrupted magic bytes, truncated files, and per-limit dimension/pixel-count/frame-count rejections; for SVG: `<script>`/`<foreignObject>`/`<style>`/animation-element removal, external `href`/`url()` rejection, entity-declaration non-expansion, and unterminated-tag handling; for JSON/plist: duplicate keys, invalid UTF-8/escapes/surrogates, out-of-range binary-plist offsets and top-object indices, a hand-built cyclic binary-plist object reference, forged huge declared object counts, and depth/node/string/number limit violations — each verified to fail with a specific diagnostic or be safely stripped, never silently accepted or crashed on. `PreviewNoNetworkTests` registers a `URLProtocol` network spy proving Markdown/JSON/plist/image/SVG parsing and sanitizing never issue a network request, with a companion test proving the spy itself is load-bearing by showing the one intentional, explicit `BoundedRemoteFetcher` opt-in path *does* reach it. `PreviewCoreWorkspaceImmutabilityTests` SHA-256/size/mtime-fingerprints real Markdown/image/JSON/plist files (including a hostile one) before and after the full preview pipeline runs and requires byte-for-byte equality. `PreviewCoreLatencyTests` cover parse/render/decode/search latency at Kod's own documented preview size limits.

Phase 11 hardens Kod into an accessible beta (SPEC 14/15): full `CodeViewport` NSAccessibility semantics and custom rotors, complete app-shell accessibility labels, keyboard/menu reachability, 300%-zoom/appearance support, a new `DiagnosticsCore` package, string localization infrastructure, and trust/crash-report/support-bundle UI. No new UI-automation testing was added or is ever run by `Scripts/verify-phase`; a manual VoiceOver checklist covers what only a human can verify (see [docs/manual-voiceover-checklist.md](docs/manual-voiceover-checklist.md)).

- **`CodeViewport` accessibility** (`Packages/KodCore/Sources/CodeViewport/CodeViewportAccessibility.swift`): `CodeAccessibilityAnnotation` tags a UTF-8 byte range with a `.symbol`/`.diagnostic`/`.reference`/`.fold`/`.gitChange` kind and a human label; `applyAccessibilityAnnotations(_:)` feeds these in from the app layer (LSP symbols/diagnostics/references, fold state, Git changes) without touching the separate visual decoration-layer pipeline. `accessibilityChildren()` exposes one lightweight, line-number-keyed element per currently *visible* source line (virtualized, matching the rest of this codebase's rendering philosophy), each with a real on-screen `accessibilityFrame()`. `accessibilityCustomRotors()` returns one `NSAccessibilityCustomRotor` per populated annotation kind (Symbols/Diagnostics/References/Folds/Git Changes — never an empty rotor for an absent kind), each walking its annotations in document order via the real `NSAccessibilityCustomRotorItemSearchDelegate` contract. `accessibilityHitTest(_:)` maps a screen point to the corresponding line element; `accessibilityAttributedString(for:)` returns real theme-colored, fonted text for a UTF-16 `NSRange`, converted through a new `SourceSnapshot.globalUTF8Offset(forGlobalUTF16Offset:)` (the exact inverse of the existing `globalUTF16Offset(forUTF8Offset:)`) so AX clients can round-trip UTF-16 ranges back to the byte offsets `selectUTF8Range`/`text(inUTF8Range:)` require; `selectUTF16Range(_:)` wraps that round-trip for selection. Read-only state is exposed via `isAccessibilitySelectorAllowed`/`accessibilityRoleDescription`/`accessibilityHelp` (selection/copy stay allowed; value-mutation does not) rather than a fabricated "editable" flag.
- **App-shell accessibility**: Explorer rows, tabs (name/pinned/preview/dirty state, distinctly-labeled close buttons), the active split group, Problems/Symbols/Search/Source Control panel rows, LSP state/restart controls, diff/blame markers and annotations, and every preview's controls (zoom, transparency, animation pause, Source/Preview toggle, remote-image opt-in) all expose real accessibility labels/values reflecting current state — severities, change kinds, and LSP states are always announced as text, never by color alone.
- **Keyboard-command registry** (`App/KodApp/KeyboardCommandRegistry.swift`): a plain `KeyboardCommand` model built by recursively flattening the *real* `NSMenu` tree `AppDelegate` constructs (`AppDelegate.buildMainMenu()`, extracted as a testable, side-effect-free function), so the registry can never drift from the actual, shipping menu — it is validated against production menu construction, not a speculative parallel list. Every primary open/search/navigate/diagnose/diff/preview command is reachable both via its keyboard shortcut and a real, enabled native menu item.
- **Zoom and appearance**: `FontSettings.sizeRange` was widened to `8...48` (comfortably covering 300% of Kod's 13pt default) with a corresponding gutter-width fix so the line-number gutter grows with digit count instead of clipping at large sizes/line counts. `ThemeStore.resolvedActiveTheme(systemIsDark:systemIsHighContrast:)`'s `systemIsHighContrast` argument is fed a real `NSWorkspace`/`NSAppearance`-derived value at its real call site (not a hardcoded `false`), and Reduce Motion (`NSWorkspace.shared.accessibilityDisplayShouldReduceMotion`) is honored by Kod's own transitions.
- **`DiagnosticsCore`** (`Packages/KodCore/Sources/DiagnosticsCore/`), a new dependency-free package (Foundation only): `DiagnosticEvent`/`DiagnosticSubsystem`/`DiagnosticLevel`/`DiagnosticContextField` model structured, category-tagged log records (a context field is tagged `.sourceText`/`.searchTerm`/`.username`/`.homePath`/`.fullPath`/`.repositoryRemote`/`.symbol`/`.diagnosticMessage`/`.environmentSecret`/`.general` at the point of creation, so redaction never has to guess). `BoundedEventLog` is an actor-based, capacity-bounded ring buffer (dropped-event count tracked and surfaced, never silently lost) whose `redactedSnapshot()` is the only thing ever shown on screen or written to a bundle. `RedactionEngine` applies deterministic (same input, same output, no randomness) category-based wholesale replacement for tagged fields plus pattern-based freeform scrubbing (home directory, absolute paths, current username, SSH/HTTPS Git remotes including embedded credentials, and environment-secret-shaped tokens like `ghp_`/`sk-`/`AKIA` prefixes or `KEY=value` assignments) for message text. `CorruptStateQuarantine` gives `FontSettingsStore`/`ThemeStore`/`WorkspaceLayoutStore` real quarantine-and-rebuild semantics (SPEC 15): a corrupt stored value is removed from its live key (so the subsystem rebuilds fresh defaults immediately rather than failing forever) and recorded — key, reason, size, timestamp, *never* the corrupt bytes — in a bounded ledger, replacing the previous silent `try?`-to-nil fallback that made "corrupt" and "never saved" indistinguishable. `CrashReportingSettings`/`CrashReportingSettingsStore` are opt-in (default `false`); `CrashReportUploadCoordinator` gates every send behind that flag and the only shipped `CrashReportTransport` is `NoopCrashReportTransport`, a permanent no-op — enabling the setting causes no network request, by construction, and a `RecordingCrashReportTransport` test double proves this without ever performing real I/O. `NetworkAttribution` is a closed enum (`.appUpdate`/`.managedServerDownload`/`.remoteMarkdownResource`/`.crashReport`) used to make Kod's UI copy for its one real opt-in network call (the remote-Markdown-image fetch) name its purpose explicitly rather than a generic prompt. `SupportBundleGenerator` assembles a manifest + the redacted event log + the quarantine ledger into a single deterministic, pretty-printed JSON document (`assertFullyRedacted` re-verifies every `.sourceText` field as a last defense-in-depth check before it could ever be written) and `write(_:to:)` saves it to a user-chosen location — no compression/archive format, so it stays trivially human-inspectable.
- **Trust, diagnostics, and privacy UI**: the trust banner gained a real "Revoke Trust" control wired to `WorkspaceTrustStore.revoke` (immediately visible and effective — running language servers for that workspace stop); a new Diagnostics settings tab (`App/KodApp/DiagnosticsView.swift`/`DiagnosticsViewModel.swift`) shows the live redacted event log with a dropped-count indicator and level filter, managed-language-server provenance (catalog/version vs. system-discovered vs. explicit override), the opt-in crash-reporting toggle (with honest copy that no real upload destination is configured), and the support-bundle export action. At least one real diagnostic event is now recorded at genuine existing failure/degraded points across language-server, Git, search, and managed-install subsystems (tagged with the correct redaction category), so the Diagnostics tab reflects real, non-fabricated app state.
- **Localization**: `App/KodApp/Localizable.xcstrings`, a real Xcode String Catalog (English-only source language — SPEC 14 requires the localization *infrastructure*, not fabricated translations, from the first release), wired into the `Kod` target's build resources. `App/KodApp/Localized.swift` wraps `String(localized:comment:)` for AppKit call sites (SwiftUI `Text("...")` literals already auto-resolve against the catalog via `LocalizedStringKey`, so those were left as-is). Every Kod-owned user-facing string in `App/KodApp/` — menu titles, control titles/labels, accessibility labels/values/hints, alert/panel copy, status/error banner text — was migrated, each with a translator-facing `comment:`. `UserFacingStringAuditTests` scans `App/KodApp/*.swift` on disk for hardcoded literals reaching a defined set of user-facing sink patterns (excluding `.accessibilityIdentifier`, log calls, and other non-user-facing carve-outs) and fails on any new violation, with a regression test proving the scanner actually catches a deliberately reintroduced one. `PseudolocalizationTests` applies a deterministic, real length-expanding transform to clipping-prone model strings (tab labels, button titles, status text) and measures them through real AppKit string-sizing APIs (`NSAttributedString`/`NSString` sizing) to prove the measurement path is genuinely exercised, not just asserting a string is non-empty.
